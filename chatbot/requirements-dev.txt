# NOTE: the Phoenix SERVER (`arize-phoenix`) is deliberately NOT here.
#
# arize-phoenix 20.9.0 pulls fastmcp-slim>=4, which needs mcp>=2.0.0, and
# chainlit 2.12.0 needs mcp<2.0.0. pip cannot satisfy both, and the error is
# a wall of resolver output that does not name the real cause.
#
# The app never imports the server -- it only needs arize-phoenix-otel, the
# exporter, which has no MCP dependency. So Phoenix runs as a service:
#
#     make phoenix        (Docker, recommended)
#
# That is the better shape anyway. A trace backend is infrastructure, not a
# library of your application.
